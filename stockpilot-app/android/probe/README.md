# StockPilot 探针 APK（M2）

**目的**：在真正投入完整功能前，用最小成本验证兼容层（卓易通）能否满足三个核心能力：

1. **前台服务能否常驻**（后台不被杀）
2. **常驻通知能否一直存在**
3. **普通通知能否正常弹出**

> 探针刻意做到：**零第三方依赖**（不用 Compose / AndroidX / OkHttp），界面全部代码构建，
> 只依赖系统 API。这样云端构建成功率最高，也最能反映"系统底层能力"。

---

## 一、构建（云端，免装 Android Studio）

仓库根目录已有流水线：`.github/workflows/build.yml`
推送代码后会自动执行：

1. `test-core`：跑核心引擎的 33 项离线断言
2. `build-probe-apk`：构建 `app-debug.apk` 并作为 Artifact 上传

**下载方式**：GitHub 仓库 → Actions → 选中最新一次运行 → 页面底部 **Artifacts** → 下载 `stockpilot-probe-apk`。

## 二、本地构建（可选，需 Android Studio）

```bash
cd android/probe
gradle :app:assembleDebug      # 或用 Android Studio 直接打开本目录
# 产物：app/build/outputs/apk/debug/app-debug.apk
```

---

## 三、安装与验收步骤

把 `app-debug.apk` 传到手机，通过**卓易通**安装。

| 步骤 | 操作 | 期望 |
|---|---|---|
| 1 | 打开 App | 看到「StockPilot 探针」界面 |
| 2 | 点「① 允许通知」 | 状态栏显示 **通知权限：已授权 ✅** |
| 3 | 点「② 加入电池优化白名单」 | 系统弹窗 → 允许；回到 App 显示 **电池白名单：已加入 ✅** |
| 4 | 点「③ 启动后台服务」 | 状态栏出现常驻通知「StockPilot 正在盯盘」 |
| 5 | **熄屏放置 10～30 分钟** | 期间每隔 5 次心跳（约 2.5 分钟）应弹出一次通知 |
| 6 | 回到 App | 查看「心跳次数 / 已运行 X 分钟」是否**连续增长** |

## 四、判定标准

| 结果 | 结论 | 下一步 |
|---|---|---|
| 常驻通知一直在，心跳连续增长，弹窗能收到 | ✅ 兼容层支持后台能力 | 放心做 M3 完整安卓版 |
| 服务被杀 / 心跳停止 / 时长不增长 | ⚠️ 后台存活受限 | 试白色名单、锁后台、关省电；仍不行则转 M4 鸿蒙原生 |
| 完全收不到通知 | ⚠️ 通知受限 | 检查通知权限与渠道；仍不行则转 M4 |

## 五、反馈什么给我

把这两张信息发我即可：

1. App 内「运行日志」最后 10 行截图
2. 熄屏 30 分钟后的「心跳次数 / 已运行 X 分钟」截图

据此就能判断兼容层能力，决定后续路线。
